## Context

站点为 React SPA（Tailwind），当前顶部导航在移动端易拥挤换行；同时各页面文案与交互提示不统一，导致“工具集合站”观感偏散。目标是在不引入大型 UI 框架的前提下，采用更标准的“App Bar + Drawer”导航模式，并对关键页面（尤其排行榜）去掉冗余提示、统一交互范式。

约束：
- 继续保持 SPA 路由与 Worker 资产托管方式不变。
- 不引入重型组件库；图标用内联 SVG（统一 24x24），样式继续用 Tailwind。

## Goals / Non-Goals

**Goals:**
- 将顶部导航替换为 App Bar + 汉堡菜单抽屉（移动端优先，PC 同样可用）。
- 精简全站导航文案：积分/议会/排行/角色/翻译；精简站点标题与副标题（移动端隐藏副标题）。
- 改进排行榜“可点击查看详情”的表达：移除每行提示，改为 chevron + hover/active 反馈 + 单处提示。

**Non-Goals:**
- 不重做整套视觉（配色/字体/版式大改）；以结构与一致性优化为主。
- 不改变任何 API、数据结构与路由路径（仅 UI 与交互提示）。
- 不引入复杂可访问性依赖（如完整 focus trap 库）；保持基础可用（ESC/遮罩点击关闭、aria）。

## Decisions

### 1) 导航采用 Drawer（而非横向滚动 Tab）

选择 Drawer 的原因：
- 站点功能入口逐渐增多，移动端横向 Tab 容易溢出/难发现。
- Drawer 能承载“短标签 + 图标”，并自然支持未来扩展（更多页面、外链等）。

### 2) 抽屉组件最小实现 + 基础可访问性

Drawer 设计：
- 打开：点击汉堡按钮
- 关闭：点击遮罩、点击菜单项、按 ESC
- 视觉：左侧滑入面板（移动端全高），PC 可保持同样行为（或在大屏提高面板宽度与留白）
- 可访问性：`role="dialog"`、`aria-modal="true"`、按钮 `aria-label`

### 3) “可点击行”的统一范式

以排行榜为代表：
- 行本身可点击
- 行右侧提供 chevron 图标作为可点击暗示
- 卡片标题行仅提示一次“点击行查看详情”
- 移除行内“点击查看详情”冗余文案

## Risks / Trade-offs

- [一致性] 不同页面目前采用不同按钮/色彩 → Mitigation：本变更优先收敛导航与列表交互；后续再做更系统的 Design Token 统一。
- [可访问性] Drawer 未做完整 focus trap → Mitigation：保持 ESC/遮罩关闭 + aria 基础；如用户反馈再引入轻量 focus trap。
