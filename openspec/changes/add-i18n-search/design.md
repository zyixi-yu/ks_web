## Context

网站将新增一个“翻译搜索”页面，用于在 SC2 本地化文件中按中文检索并展示中英对照。数据来源为 Cloudflare KV，两个 key 分别为 `ks_gs_new_cn` 与 `ks_gs_new_en`，内容格式均为 `key=value` 且按 key 一一对应。KV 更新频率约 1–2 天一次，允许一定延迟生效。

约束：
- 站点架构为 React SPA + Cloudflare Worker（Hono）提供 `/api/*`。
- 本能力对外不需要写接口，仅新增读接口即可（搜索）。

## Goals / Non-Goals

**Goals:**
- 新增导航入口与独立页面，支持中文子串搜索与分页展示（每页 20）。
- Worker 提供搜索 API，并在内存中缓存解析后的词库以避免每次请求重复解析大文本。
- 文本展示时清洗本地化标签：换行标签转为换行；数值引用标签用 `X` 占位；其他标签忽略/去除。

**Non-Goals:**
- 不做复杂索引（倒排/分词）与模糊匹配；仅做中文子串匹配与多关键词 AND。
- 不做权限控制与审计；该功能面向公开查询。
- 不做实时热更新；KV 更新允许延迟生效。

## Decisions

### 1) 搜索在 Worker 侧完成

选择在 Worker 实现 `GET /api/i18n/search`，返回分页结果，前端仅负责表单、分页与渲染。

理由：
- 两个本地化文件体积大（MB 级），前端全量加载与解析会增加首屏成本。
- Worker 侧可以内存缓存解析结果，用户请求响应更稳定。

### 2) 内存缓存 + 请求驱动刷新（非定时器）

Worker 内存缓存结构：
- `Map<key, { en: string; cn: string }>`（值为“已清洗”的可展示文本）
- `loadedAt`（最近一次构建缓存的时间）

刷新策略（请求驱动）：
- 首次请求：从 KV 拉取 `ks_gs_new_cn` / `ks_gs_new_en`，解析并构建 Map。
- 后续请求：优先使用 Map；当 `now - loadedAt` 超过一个较长检查间隔（例如 1 小时）时，使用 `ctx.waitUntil` 后台重建缓存并更新 `loadedAt`。

理由：
- KV 更新频率低，允许延迟；后台刷新可避免把大文本解析时间摊到用户请求上。
- 不依赖 `setInterval` 等在 Workers 上不可靠的定时器。

### 3) 标签清洗规则实现为纯函数

实现一个 `sanitizeSc2LocalizationText(text)`：
- 将 `<n/>`（大小写不敏感）替换为 `\n`
- 将 `<d .../>`（大小写不敏感）替换为 `X`
- 去除剩余 `<...>` 标签（保留标签包裹的纯文本内容）

## Risks / Trade-offs

- [性能] 每次查询需要遍历词库做子串匹配 → Mitigation：内存缓存 + 结果分页；后续如压力上升再引入索引/预计算。
- [一致性] 多边缘实例内存缓存可能短时间不一致 → Mitigation：允许延迟更新；通过“检查间隔”控制最长滞后时间。
- [数据质量] 中英文件可能存在缺 key 或重复 key → Mitigation：解析时以 key 为准，缺失另一语言时返回空字符串并保留 key，便于发现问题。
